# pfd-fit gate run — the control now states why its lanes are dead (issue #201)

Full 0006 fit-gate run (`sim/pfd-fit/run.sh`) with the `ctl_1g` control
instrumented. Until this run the control measured only its four ports, so its
all-zero lanes could have been the documented reset-polarity failure or a broken
arm. Its request now carries DUT-internal probes, and `grade.py` accepts the
control's FAIL only for a stated reason it reads off them. **Criteria C1–C3, the
`pfd_*` decks and requests and `design/netlist/pfd.spice` are unchanged**: every
deck and both `pfd_*` requests are byte-identical to `../20261123T001411Z/`, and
`decks/pfd.spice` here is sha256
`218423053287320d97e41fea5fdc97328f6a08c061f8834ae768e3519714829d`. No `spec/`
row and no decision record changed. Results are **simulated, never measured**.

## Result: gate PASS; the control fails for a stated reason at every corner

`pfd_1g` and `pfd_500m` PASS C1–C3 at all three corners and reproduce
`../20261123T001411Z/`: C2 reset-pulse width 130..132 ps (tt), 205..208 ps (ss)
and 87..88 ps (ff), at both frequencies.

`ctl_1g` — the committed `srlatch_buf` latch with the sibling's reset polarity
(`pfd_sib` in `make_bench.py`: `reset = NAND(up_qn, dn_qn)`, two inverters after
the NAND) — FAILS at all three corners with no lane pulse at any offset (`wUP =
wDN = 0` ps, C1 ratio 0.00, C2 width 0 ps). The probes say why:

| corner | edge detectors | `reset` at rest | storage nodes `up_qn`, `dn_qn` | lanes UP, DN | dead state |
|---|---|---|---|---|---|
| tt/1.200V/27C | fire: 38 + 38 crossings | 0.000 V (1.1e-7 V), deasserted | never cross; ≥ 1.155 V | never cross; 1.201 V | **stuck set** |
| ss/1.080V/125C | fire: 38 + 38 | 1.080 V, asserted | pulse on every edge: 38 + 38 | never cross; ≤ 0.003 V | **held in reset** |
| ff/1.320V/−40C | fire: 38 + 38 | 0.000 V (1.6e-7 V), deasserted | never cross; ≥ 1.270 V | never cross; 1.321 V | **stuck set** |

19 REF and 19 FB edges per deck, so 38 crossings is one rise and one fall per
input edge; "at rest" is the cycle before the first REF edge (4..4.9 ns).
`grade.py` reports `FAILS FOR THE STATED REASON -- stuck set` at tt and ff and
`-- held in reset` at ss. Any other reading — a contradicted clause, a control
that passes, a missing probe or no control envelope at all — is a bench defect
and makes the gate exit non-zero.

## What the probes show

The all-zero lanes are **one conclusion with two mechanisms**: the two stable
rest states of the sibling's reset. Which one the circuit starts in depends on
the corner.

1. **ss — held in reset.** `reset` is asserted at rest (1.080 V), i.e. both
   latches are reset. With `R` held at 1 the latch passes its set input to the
   storage node, so `up_qn`/`dn_qn` pulse on every input edge — at offset 0 they
   rise 259.3 ps and fall 407.1 ps after the REF crossing, under set pulses of
   109.6..288.9 ps — while the lane stays low. `reset` deasserts only where the
   two storage-node pulses overlap: 13 cycles, the offsets −20..+20 ps. Lagging
   by the NAND and two inverters, its dip (41..76 ps wide at VDD/2, minimum
   0.162 V) runs 444.9..520.7 ps, after both storage-node pulses have ended. The
   latch never sees `S = 1` together with `R = 0`, so no lane pulse is released:
   UP and DN never exceed 3 mV.
2. **tt, ff — stuck set.** The circuit rests with both latches set: `up_qn` and
   `dn_qn` high, `reset = NAND(1, 1)` a driven logic low, and UP and DN at VDD
   before the first REF edge. A set pulse cannot change a latch that is already
   set and nothing ever resets it: `reset`, both storage nodes and both lanes
   never cross VDD/2. `../20261123T012643Z/` (single-corner local diagnostic,
   not a gate run) reads the rest of the latch at these two corners: `up_qb` and
   `dn_qb` low (−0.010..0.009 V), the NAND output `reset_raw` low (2e-7..3e-7 V)
   and `reset_d1` at VDD.

The run's `crossings_*.raw` dumps (local artifacts, not committed) read the same
values at their first sample, t = 0: these are the operating points the
transients start from, not later transitions.

In both states the edge detectors fire on every input edge, so the stimulus
reaches the latch inputs and the arm is not broken. The committed polarity
(`reset = up_qn AND dn_qn`, NAND + one inverter) has neither dead state: at
`(0, 0)` its reset is deasserted, so a set pulse releases the lane, and at
`(1, 1)` it is asserted, which is the self-terminating reset pulse C2 measures.
That is the argument of
[0008](../../../../spec/decisions/0008-false-lock-argument.md) read off the DUT
instead of the netlist, and completed: with the sibling's polarity neither rest
state releases a lane pulse.

## What this run does not establish

- Which state a physical power-up would take is not simulated: each corner shows
  the state its operating point resolves to. Both dead rest states are observed,
  one per corner, not both at every corner.
- At these probes "held in reset" cannot be told from a reset tied high, nor
  "stuck set" from a reset that never reaches the latch. The control differs from
  `pfd` in the reset chain alone (`SIBLING_POLARITY`), which is what makes the
  comparison a polarity comparison.
- Only the three `reduced_set` corners were run, as for every earlier run of this
  gate; mismatch, the 45-corner grade and post-layout effects remain open.

## Scope

Bench evidence only. C1–C3, every `spec/` row and every decision record are
unchanged. For this latch and these decks "held in reset" is what ss shows; tt
and ff show the stuck-set state. Whether the run-2 control of decision 0011 (the
earlier `srlatch_fast` latch) was held in reset at tt was not probed then and is
not established here.
